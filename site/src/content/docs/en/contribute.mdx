## The diagnostic report

**Settings › About › Copy report** copies the version, the system and the last lines of the log, keys and passwords masked. Read it before pasting: it may contain server or project names.

## Proposing a change

1. Fork the repository and create a branch from `main`.
2. `npm install`, then `npm run dev` to run the app (Node.js 22, Windows).
3. Add or update the tests: Vitest in `tests/main`, Playwright in `tests/e2e`.
4. `npm run check` must pass: types, lint, tests, build. Then `npm run build` and `npm run test:e2e` for the end-to-end tests.
5. Open a pull request: its template recalls what to check.

The CI runs on your pull request (Windows, about 5 minutes; for a first contribution, a maintainer starts it in one click). The code layout is described in [docs/dev/architecture.md](https://github.com/victhille/devforge/blob/main/docs/dev/architecture.md) (in French).

## House rules

| Rule | How |
|---|---|
| Conventional commits | `feat(zone): …`, `fix(zone): …`, `docs: …`: the changelog is built from them |
| Interface texts | always in `fr.ts` and `en.ts`, never hard-coded |
| Secrets | never sent to the interface, never shown nor written in clear |
| Nothing personal | no real IP, server or account; examples: `203.0.113.10`, `my-server`, `example.com` |

## Improve this site

Each page has an **Edit page** link at the bottom: it opens its source in [`site/`](https://github.com/victhille/devforge/tree/main/site) on GitHub. A typo, an unclear explanation: a small pull request is enough.
