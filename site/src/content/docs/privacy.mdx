## Ce qui reste sur ton PC

Tout ce que DevForge sait est dans son dossier, `%APPDATA%\DevForge`, en fichiers JSON : projets, serveurs, bases, réglages, historique de Forgy. Rien n'est gardé ailleurs.

- Une sauvegarde est faite avant chaque changement du format de données ; les 5 dernières sont gardées.
- Le journal local note erreurs et évènements, secrets masqués.
- **Paramètres › Données › Tout effacer** remet DevForge à zéro.

Voir [Données, export et remise à zéro](/devforge/settings/data/).

## Tes mots de passe et tes clés

- **Chiffrés par Windows** (DPAPI), liés à ton compte Windows : copiés sur un autre PC ou un autre compte, ils sont illisibles.
- **Jamais renvoyés à l'écran** : l'interface reçoit seulement « renseigné » ou « aucun ». Même la page n'y a pas accès, seul le processus principal les déchiffre au moment de s'en servir.
- **Absents de l'export** de la configuration : ils seront à ressaisir sur l'autre PC.
- **Masqués** dans le journal et le rapport de diagnostic.
- La synchronisation du `.env` avec un serveur compare l'état de chaque clé (identique, différente, seulement ici), jamais les valeurs.

## Ce qui sort de ton PC, et quand

| Vers | Quand | Quoi |
|---|---|---|
| GitHub | 15 secondes après le démarrage, puis toutes les 6 heures ; à couper dans **Paramètres › Mises à jour** | la recherche d'une mise à jour, et son téléchargement ; aucun jeton n'est envoyé |
| GitHub | toutes les 5 minutes, si GitHub est connecté ; à couper dans **Paramètres › Général › Alertes du CI GitHub** (« Aucune ») | l'état des workflows de tes projets favoris (ou de tous), avec ton jeton GitHub |
| Le fournisseur d'IA que tu choisis | quand tu écris à Forgy | ta question et son contexte (voir plus bas) |
| Hugging Face | à la première dictée | le téléchargement du modèle de reconnaissance vocale ; ta voix, elle, ne quitte jamais le PC |
| Tes serveurs, GitHub, Vercel, n8n, ntfy… | quand tu te sers de la fonction, ou en fond une fois réglée (surveillance d'un serveur, sondes d'URL, sauvegardes) | ce que la fonction demande, avec les identifiants que tu as donnés |

Le récepteur de [webhooks](/devforge/data/webhooks/) n'écoute que sur ce PC (`127.0.0.1`) : il n'est pas joignable depuis le réseau.

## Ce que Forgy envoie

Forgy fonctionne avec le fournisseur d'IA que tu choisis, avec ta clé : Anthropic (Claude), OpenAI, Google Gemini, Mistral AI, xAI (Grok), OpenRouter, Groq, DeepSeek ou un serveur compatible OpenAI ; ou Ollama, qui tourne sur ton PC. Voir [les fournisseurs](/devforge/forgy/assistant/#fournisseurs). Chaque question envoie, au fournisseur choisi seulement :

- ta question et la conversation en cours ;
- au premier message sur un projet : son nom, son chemin, son framework, l'état Git, les fichiers à la racine, les scripts, les dépendances et le début du README ;
- le contexte de la page ouverte, si la pastille 📎 est active : la **structure** d'une base, jamais ses données ; une requête de l'API Tester, en-têtes sensibles masqués ; les dernières lignes de logs affichées ;
- ce que Forgy a lu pour répondre : fichiers du projet, diff Git, état Docker… Les fichiers de secrets (`.env`, clés, `credentials.json`, `secrets.json`, `wp-config.php`…) ne sont jamais lus.
- sur la page [Vercel](/devforge/online/vercel/), **Demander à Forgy** sur un déploiement en échec : la fin de son journal de build (80 lignes au plus), les secrets reconnus masqués.

Avec Claude, Forgy peut aussi **chercher sur le web** : la recherche est faite par Anthropic, à partir de ta question.

Ce que tu envoies relève alors des conditions du fournisseur, et de son pays : les États-Unis pour Anthropic, OpenAI, Google, xAI, OpenRouter et Groq, la France (Union européenne) pour Mistral AI, la Chine pour DeepSeek ; avec Ollama, rien ne quitte ton PC. DevForge, lui, ne reçoit rien : il n'a pas de serveur.

Pour **agir** (commit, `.env`, conteneur, SQL…), Forgy propose une carte : rien ne s'exécute avant ton clic. Le réglage **Auto pour les actions sûres** laisse partir seules les actions annulables ou en lecture ; push, pull, écriture SQL et ports demandent toujours ton accord. Un budget mensuel arrête Forgy une fois atteint.

Voir [Forgy](/devforge/forgy/assistant/) et [ses actions](/devforge/forgy/actions/).

## Le rapport de diagnostic

**Paramètres › À propos › Copier le rapport** copie la version, le système et les dernières lignes du journal, secrets masqués. **Rien n'est envoyé** : tu le colles où tu veux. Relis-le avant : il peut contenir des noms de serveurs ou de projets.

## Signature du code

L'installeur n'est **pas encore signé** : Windows affiche « Windows a protégé votre ordinateur » au premier lancement. En attendant, l'empreinte SHA-256 de chaque installeur est publiée pour [vérifier le fichier](/devforge/download/#vérifier-linstalleur).

Règles de signature, valables dès qu'un certificat sera en place :

- Seuls les installeurs construits par GitHub Actions, à partir d'un tag de version du [dépôt public](https://github.com/victhille/devforge), sont signés. Rien n'est signé depuis un PC.
- Le code source, les scripts de build et la configuration de la CI sont tous dans ce dépôt, sous licence GPL-3.0 ; DevForge ne contient aucun composant propriétaire.
- Auteur, relecteur et approbateur de chaque signature : [victhille](https://github.com/victhille), mainteneur du projet.
- DevForge n'envoie aucune information à un autre système en réseau en dehors de ce que liste [Ce qui sort de ton PC](#ce-qui-sort-de-ton-pc-et-quand), où chaque envoi automatique peut être coupé.

## Signaler une faille

Pas dans une issue publique : utilise le signalement privé de GitHub (onglet **Security**, **Report a vulnerability**). Seuls les mainteneurs le voient. Voir [Contribuer](/devforge/contribute/).

## Ce site

Ni cookie ni mesure d'audience. La page d'accueil et la page de téléchargement interrogent l'API publique de GitHub pour connaître la dernière version : comme pour toute page web, GitHub reçoit alors ton adresse IP. Le site est hébergé par GitHub Pages, voir les [mentions légales](/devforge/legal/).
