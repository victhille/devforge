# Feuille de route v3.9 — Concevoir avant de coder

**Cap** : DevForge aide à concevoir un projet avant de l'écrire (MCD, MLD, MPD, SQL, diagrammes UML), relie ce qu'on dessine à la vraie base du projet, et la création d'un projet ressemble enfin à sa maquette.
**Base** : v3.8.1.

## Vue d'ensemble

| Lot | Contenu | Taille |
|---|---|---|
| 1 | Nouveau projet comme la maquette (après le choix du framework) | M |
| 2 | Page Modélisation et éditeur MCD | L |
| 3 | MLD et MPD générés, SQL | M |
| 4 | La base liée : écarts, script, import depuis une base | M |
| 5 | Diagrammes UML et logigrammes | M |
| 6 | Documentation et vérification | S |

Taille : S ≈ 1 à 2 sessions, M ≈ 3 à 5, L ≈ 6 et plus.

Maquettes validées (canvas *DevForge — maquette 2.0*) : zone « Créer un projet » (lot 1), zone « Données · schéma et modélisation » (lots 2 à 5).

## Lot 1 — Nouveau projet comme la maquette

Le choix du framework (étape 1, avec Mes modèles) ne bouge pas. Les étapes d'après prennent la forme de la maquette :

- un en-tête commun **Nouveau projet** et une **barre d'étapes** : celles faites en vert avec leur valeur (*1 · Framework : Symfony 7.3*, *2 · Nom : boutique*), celles en cours en surbrillance, celles à venir en contour ; un clic sur une étape faite y revient ;
- en bas, toujours au même endroit : **Retour** à gauche, une aide au milieu, **Continuer** (ou **Créer le projet**) à droite ;
- **Base de données et options** sur un même écran (étapes 3 et 4) : les moteurs en cartes (*PostgreSQL 16 · dans Docker, recommandé*…), nom et port, « DevForge va : » ; les options en cartes à cocher, un titre et une phrase chacune ;
- **Git et GitHub** puis **Récapitulatif** sur un même écran (étapes 5 et 6) : dépôt et premier commit, dépôt GitHub (le compte de `gh`), privé ou public, nom du dépôt `compte/nom`, ouvrir dans l'IDE, **en faire le projet actif** ; le récapitulatif en commandes `$ …`, la durée estimée, « Rien n'est publié avant ton clic » ;
- **Créer le projet** reste sur la page : une carte **Création en cours** (*5 étapes sur 8*, le temps écoulé, une barre, chaque étape faite, en cours ou à venir), puis **Ouvrir le projet** ; la console garde le journal complet.

Les projets sans base ni options (React, Vue…) et les modèles de l'utilisateur gardent leurs étapes, dans le même cadre.

**Fini quand** un projet Symfony avec PostgreSQL, quatre options et un dépôt GitHub privé se crée de bout en bout depuis ces écrans, en suivant la progression sur la page, et devient le projet actif.

## Lot 2 — Page Modélisation et éditeur MCD

- Une page **Modélisation** (menu Données & API), les modèles rangés par projet (un sélecteur de projet) : **la chaîne du projet** (MCD → MLD → MPD → SQL → base liée, avec l'état de chacun), **les modèles du projet** (aperçu, type, date), **Créer un modèle** (MCD, MPD, cas d'utilisation, classes, séquence, logigramme, architecture, depuis une base).
- Les modèles sont des fichiers du projet, dans `conception/` (`boutique.mcd.json`…), donc versionnés avec Git ; un projet sans dossier n'en a pas.
- **L'éditeur MCD** (Merise) : entités (nom, attributs, identifiant souligné), associations (nom, attributs portés), liens avec cardinalités (0,1 · 1,1 · 0,n · 1,n) ; palette, déplacer, relier d'un bord à l'autre, un clic sur une patte change sa cardinalité ; panneau de l'élément choisi (attributs, type, identifiant) ; notes ; même canevas que le schéma (zoom, Ajuster, mini-carte), enregistré au fil des changements ; annuler / rétablir.
- **Vérifier** : chaque entité a un identifiant, chaque lien sa cardinalité, un attribut sans type (texte par défaut), deux noms identiques.
- Export PNG et SVG.

**Fini quand** le MCD d'une boutique (6 entités, 5 associations) se dessine, se vérifie, s'enregistre dans le projet et se rouvre à l'identique.

## Lot 3 — MLD et MPD générés, SQL

- **MLD** généré du MCD, en texte (`COMMANDE (id_commande, passee_le, #id_client)`), chaque relation avec la règle appliquée (entité → relation, 1,1 → clé étrangère, n-n → table d'association) ; réglages de nommage (snake_case, `id`, `client_id`, nom des tables d'association).
- **MPD** : les tables du MLD avec leurs types pour le moteur du projet (MySQL, PostgreSQL, SQLite), les clés, `NOT NULL`, `UNIQUE` ; dessiné comme le schéma de la base ; un MPD se modifie aussi à la main (type, longueur, index).
- **SQL** : le script `CREATE TABLE` du MPD, à côté, copiable, écrit dans `conception/schema.sql` ; changer de moteur réécrit les types.

**Fini quand** le MCD de la boutique donne un MPD et un script qui s'exécute sans erreur dans un vrai PostgreSQL, MySQL et SQLite.

## Lot 4 — La base liée : écarts, script, import

- Le MPD comparé à la **connexion liée au projet** : tables en plus ou en moins, colonnes, types, clés ; « ▲ 2 différences » dans la chaîne et sur le MPD.
- **Voir le script** qui rattrape l'écart (`CREATE`, `ALTER`) ; **Appliquer** après confirmation, une suppression en rouge avec une sauvegarde proposée avant ; **Prendre la base dans le MPD** pour l'autre sens.
- **Importer depuis une base** : lit une connexion, dessine le MPD, puis en déduit un MCD (les tables de liaison redeviennent des associations, les clés étrangères des liens 1,1 — 0,n).
- Symfony : proposer une migration Doctrine plutôt qu'un `ALTER` direct.

**Fini quand** une base réelle importée donne un MCD lisible, et qu'un changement du MPD s'applique à la base de développement du projet.

## Lot 5 — Diagrammes UML et logigrammes

Le même canevas avec une palette par type :

- **Cas d'utilisation** : acteurs, système, cas, association, `include`, `extend`, généralisation ; un scénario par cas ; **Créer les tâches dans Notes** (une tâche par cas, dans l'onglet Notes du projet) ;
- **Classes** : classes, interfaces, attributs, méthodes, héritage, association, composition ;
- **Séquence** : participants, lignes de vie, messages, retours ;
- **Logigramme** : début et fin, étapes, décisions, entrées et sorties ;
- **Architecture** : services, bases, files, clients, passerelles.

Notes, export PNG et SVG, enregistrés dans `conception/` comme le MCD.

**Fini quand** chaque type se dessine, s'enregistre et se rouvre, et qu'un diagramme de cas d'utilisation remplit l'onglet Notes.

## Lot 6 — Documentation et vérification

- Pages du site (français et anglais) : Nouveau projet (les écrans refaits), Modélisation (MCD, MLD, MPD, SQL, base liée, UML) ; les outils de Forgy pour lire un modèle.
- Vérifié pour de vrai : un projet Symfony créé de bout en bout ; un MCD qui devient une base PostgreSQL, MySQL et SQLite ; une vraie base importée puis modifiée.

**Fini quand** chaque nouveauté a sa page dans les deux langues et que les vérifications ci-dessus passent.
