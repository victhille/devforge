# Feuille de route v3.3 — Le projet au complet

**Cap** : depuis la fiche d'un projet, tout ce qui le concerne se voit et se règle sans en sortir : sa base de données, et ses paquets (npm et Composer), avec leur mise à jour.
**Base** : v3.2.0.

## Vue d'ensemble

| Lot | Contenu | Taille |
|---|---|---|
| 1 | La base de données dans la fiche projet, et le retour au projet | M |
| 2 | Onglet Paquets : `package.json` (npm, pnpm, yarn) | L |
| 3 | Onglet Paquets : `composer.json` (PHP, Sail compris) | M |
| 4 | Forgy et les paquets | S |
| 5 | Documentation du site et vérification | S |

Taille : S ≈ 1 à 2 sessions, M ≈ 3 à 5, L ≈ 6 et plus.

Le portage macOS et Linux ([étude](../dev/portage.md)) est pour une version plus tardive.

## Lot 1 — La base de données dans la fiche projet

Aujourd'hui, l'onglet Base de données de la fiche projet liste les bases liées ; « Ouvrir » mène à la page Base de données, qui n'a pas de chemin de retour vers le projet.
- L'explorateur de la page Base de données (arbre des tables, aperçu, données, structure, SQL) devient un composant à part, affiché **directement dans l'onglet** pour la base liée ; plusieurs bases liées : un sélecteur en haut.
- La base se connecte à l'ouverture de l'onglet, pas avant (une fiche projet reste rapide).
- « Ouvrir en grand » garde le lien vers la page Base de données ; ouverte depuis un projet, cette page montre **« ← Retour au projet »**.
- Rien ne change pour la page Base de données ouverte depuis le menu.

**Fini quand** on consulte les tables, les données et lance une requête depuis la fiche projet, et qu'un aller-retour vers la page Base de données ramène au même projet, sur le même onglet.

**Fait** :
- `DbExplorer` (`src/renderer/src/features/database/DbExplorer.tsx`) : les tables dans leur propre colonne repliable, puis aperçu, données, structure, relations, infos et SQL, et le contexte donné à Forgy ; il se connecte quand il s'affiche ;
- la page Base de données n'a plus que la liste des connexions, à côté de l'explorateur de celle choisie ;
- l'onglet Base de données du projet affiche la première base liée ; « Afficher » sur une autre ligne en change ; la tuile de l'aperçu y mène aussi ;
- « Ouvrir en grand » ouvre la page Base de données avec `?from=<projet>` : elle montre « ← Retour à {projet} », qui ramène sur l'onglet Base de données du projet ;
- test : `tests/e2e/hub.e2e.ts` (la table et ses lignes dans l'onglet, l'aller-retour vers la page).

## Lot 2 — Onglet Paquets : npm

Un onglet **Paquets** dans la fiche projet, quand le projet a un `package.json` (y compris dans des sous-dossiers, `node_modules` exclu : un dépôt à plusieurs paquets montre chacun).
- **Liste** : nom, version demandée (`^1.2.0`), version installée (lue dans `node_modules`), dernière version publiée (registre npm), dépendance ou dépendance de développement.
- **Écart** : à jour, correctif, mineure, **majeure** (couleur et filtre) ; paquet absent de `node_modules` (« installer d'abord »).
- **Vulnérabilités** : le résumé de `npm audit` (ou l'équivalent pnpm / yarn) par gravité, et les paquets concernés.
- **Mettre à jour** : un paquet, une sélection, ou « tout ce qui reste compatible » (correctifs et mineures) ; une montée de version majeure demande une confirmation qui le dit et renvoie vers les notes de version du paquet. La commande vient du gestionnaire du projet (npm, pnpm, yarn), son journal s'affiche en direct, et le `package.json` est sauvegardé avant (pour revenir en arrière si l'installation échoue).
- Rien ne se met à jour tout seul.

**Fini quand** un projet npm, pnpm ou yarn montre ses paquets en retard, et qu'une mise à jour choisie s'applique, avec retour en arrière si elle échoue.

## Lot 3 — Onglet Paquets : Composer

Le même onglet pour `composer.json` (Symfony, Laravel, PHP) :
- `composer show --direct` et `composer outdated --direct --format=json` : version demandée, installée, dernière, écart ; `composer audit` pour les vulnérabilités ;
- mises à jour avec `composer update <paquet> --with-dependencies` (ou `composer require` pour une majeure, après confirmation) ;
- projet Laravel Sail : les commandes passent dans le conteneur (`docker compose exec -u sail laravel.test composer …`), comme les autres commandes de l'atelier ;
- Composer absent : « Composer n'est pas installé » et le lien d'installation, sans erreur.

**Fini quand** un projet Symfony et un projet Laravel (avec et sans Sail) montrent et mettent à jour leurs paquets.

## Lot 4 — Forgy et les paquets

- Outil de lecture `project_packages` : Forgy peut dire ce qui est en retard ou vulnérable dans un projet.
- Action `update_packages` (carte à valider, comme les autres) : mettre à jour les paquets qu'il propose ; annulable en restaurant les fichiers sauvegardés.

**Fini quand** « qu'est-ce qui est en retard dans ce projet ? » donne une réponse juste, et une mise à jour proposée par Forgy passe par une carte.

## Lot 5 — Documentation et vérification

- Pages du site : la base de données dans la fiche projet, l'onglet Paquets (npm et Composer) ; liens d'aide (F1) de l'onglet vers sa page.
- Vérifié sur de vrais projets : un projet Node, un Next.js, un Symfony, un Laravel avec Sail.

**Fini quand** chaque nouveauté a sa page de doc dans les deux langues, et les quatre projets passent.
