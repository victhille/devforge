# Feuille de route v3.6 — Finir ce qui est commencé

**Cap** : ce que DevForge montre, il sait aussi le faire : mettre à jour les paquets de tous les langages, modifier les lignes d'une table, et trouver un texte dans tout un projet.
**Base** : v3.5.3, plus la correction poussée et pas encore publiée (`d6a1e95` : un fichier s'ouvre dans la fenêtre de son projet). Elle partira avec la 3.6.

## Lot 1 — Paquets des autres langages : mise à jour et audit

Depuis la 3.5.3, leurs cartes comparent les versions et donnent la commande à lancer. Elles gagnent les mêmes boutons que npm et Composer : **Mettre à jour**, **Passer à** *version*, **Mettre à jour la sélection**, **Mettre à jour les compatibles**, **Vérifier les vulnérabilités**.

| Outil | Mise à jour (dans l'intervalle / au-delà) | Audit |
|---|---|---|
| pip (`requirements*.txt`) | `pip install -U "nom<borne>"` / `pip install -U nom`, puis la ligne du fichier réécrite si l'intervalle change | `pip-audit -r` |
| Poetry | `poetry update nom` / `poetry add nom@latest` | `pip-audit` (export du lock) |
| uv | `uv lock --upgrade-package nom` puis `uv sync` / `uv add nom@latest` | `pip-audit` |
| Pipenv | `pipenv update nom` | `pipenv check` |
| Cargo | `cargo update -p nom` / `cargo add nom@version` | `cargo audit` |
| Go | `go get nom@patch` ou `@latest`, puis `go mod tidy` | `govulncheck ./...` |
| Bundler | `bundle update nom` / Gemfile réécrit, puis `bundle install` | `bundle audit` |
| pub | `dart pub upgrade nom` / `dart pub add nom:^version` (`flutter` pour un projet Flutter) | — |

- **Comme pour npm** : le manifeste et le lockfile sont sauvegardés avant ; si la commande échoue, ils sont remis tels quels et le journal reste affiché.
- **Python** : les commandes passent par l'environnement virtuel du projet (`.venv\Scripts\python -m pip`), jamais par le Python du système. Sans environnement virtuel, pas de mise à jour pip : la carte le dit et propose de le créer (`python -m venv .venv`).
- **Outil absent** (`cargo audit`, `pip-audit`, `govulncheck`…) : signalé comme Composer aujourd'hui, avec la commande qui l'installe ; la mise à jour reste possible.
- **.NET et Java** restent en lecture seule (leurs mises à jour passent par l'IDE ou par des plugins rarement installés).

**Fini quand** un projet Python (pip et Poetry) et un projet Rust se mettent à jour depuis l'onglet, qu'un échec remet les fichiers en place, et qu'un audit trouve une vulnérabilité connue.

## Lot 2 — Forgy et les nouveaux langages

- `project_packages` donne déjà leurs versions ; il ajoute l'audit quand l'outil est là.
- `update_packages` les met à jour par une carte à valider, avec le même retour en arrière que npm.

**Fini quand** Forgy propose, puis fait après accord, la mise à jour d'un paquet Python.

## Lot 3 — Modifier les lignes d'une table

Dans **Parcourir** (page Base de données et onglet de la fiche projet) :
- **double-clic** sur une cellule pour la modifier ; **NULL** d'un clic ; Échap annule ; les cases booléennes et les dates ont leur champ ;
- **Ajouter une ligne** (vide, en haut ; les colonnes auto-incrémentées et à défaut restent vides) et **Supprimer** les lignes cochées ;
- les changements en attente sont surlignés ; **Appliquer (n modifications)** montre les requêtes `UPDATE` / `INSERT` / `DELETE` avant de les lancer, **Annuler** les oublie.

Règles :
- une ligne n'est modifiable que si la table a une **clé primaire** (sinon on ne sait pas quelle ligne changer) : sans clé, la grille le dit et reste en lecture ;
- les valeurs partent **en paramètres**, jamais collées dans le SQL ;
- tout part dans **une transaction** : une erreur et rien n'est gardé, le message de la base reste affiché ;
- les vues, et les résultats de l'onglet SQL, restent en lecture.

**Fini quand**, sur PostgreSQL, MySQL et SQLite, une cellule modifiée, une ligne ajoutée et une ligne supprimée partent en une fois, qu'une erreur n'en garde aucune, et qu'une table sans clé primaire refuse poliment.

## Lot 4 — Importer et exporter une table

- **Exporter** une table, ou le résultat d'une requête, dans un fichier : CSV, JSON, ou SQL (`INSERT`, avec ou sans `CREATE TABLE`). Toute la table, pas seulement la page affichée, par paquets de 1 000 lignes.
- **Importer** un CSV dans une table : séparateur et encodage reconnus, colonnes associées par leur nom (modifiables), aperçu des 10 premières lignes, puis insertion dans une transaction ; les lignes refusées sont listées avec la raison.
- Les fichiers passent par la boîte de dialogue de Windows ; rien n'est lu ni écrit ailleurs.

**Fini quand** une table de 10 000 lignes s'exporte dans les trois formats et qu'un CSV s'importe, ou est refusé en entier avec la ligne fautive.

## Lot 5 — Rechercher dans tout le projet

En haut de l'onglet **Fichiers** :
- un champ de recherche : texte ou **regex**, options *casse* et *mot entier*, et un filtre de fichiers (`*.ts`, `src/**`) ;
- les résultats groupés par fichier, la ligne trouvée surlignée, le nombre de résultats ;
- un clic ouvre le fichier dans l'aperçu, **à la ligne** ; un bouton l'ouvre dans l'IDE à cette ligne (`code -g fichier:ligne`, `--line` pour JetBrains).

Règles : la recherche tourne dans le processus principal, saute `node_modules`, `vendor`, `.git`, les builds, les environnements virtuels et les fichiers binaires ; elle part 300 ms après la dernière touche, s'arrête à 1 000 résultats et s'annule à la frappe suivante.

**Fini quand** une recherche dans DevForge lui-même répond en moins d'une seconde et qu'un résultat s'ouvre à la bonne ligne, dans l'aperçu et dans VS Code.

## Lot 6 — Documentation et vérification

- Pages du site (français et anglais) : Paquets (mise à jour et audit des autres langages), Base de données (modifier les lignes, importer, exporter), Projets (la recherche).
- Vérifié sur de vrais projets : un projet Python avec `.venv`, un projet Rust, une base MySQL et une base PostgreSQL (pas seulement SQLite, voir la 3.5.1).

**Fini quand** chaque nouveauté a sa page dans les deux langues et que les vérifications ci-dessus passent.

## Ensuite : la v3.7

Déjà prête, à publier avec elle (retour d'essai de la 3.6.0) : la recherche des Fichiers ne s'élargit plus au-delà de la carte avec de très longues lignes (le champ et la barre de défilement restent visibles), et une ligne trouvée plusieurs fois n'apparaît qu'une fois, chaque occurrence surlignée.

Deux nouveaux onglets de la fiche projet, qui vont ensemble :
- **Tests** : lancer Vitest / Jest, PHPUnit, pytest (puis Playwright, Go, Cargo) et voir chaque test, réussi ou échoué, avec le message, l'attendu et le reçu, **Relancer les échecs**, **Expliquer avec Forgy** ;
- **Git dans l'arbre de fichiers** : fichiers modifiés, nouveaux et supprimés en couleur, le diff d'un fichier dans l'aperçu, filtre **Modifiés seulement**.

Plus tard, au fil des envies : schéma de la base, modèles de projet, notes et tâches par projet, tableau de bord d'activité, alertes du CI GitHub ; puis macOS et Linux ([étude](../dev/portage.md)).
