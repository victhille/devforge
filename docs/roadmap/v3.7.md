# Feuille de route v3.7 — Tester et suivre ses changements

**Cap** : depuis la fiche d'un projet, on lance ses tests et on voit chacun, réussi ou échoué, avec ce qui a échoué et pourquoi ; et l'arbre de fichiers montre ce qui a changé depuis le dernier commit.
**Base** : v3.6.0, plus la correction de la recherche (`087dfc8`, retour d'essai de la 3.6.0) qui part avec la 3.7.

## Vue d'ensemble

| Lot | Contenu | Taille |
|---|---|---|
| 1 | Onglet Tests : trouver l'outil, lancer, lire les résultats | L |
| 2 | Onglet Tests : les échecs, relancer, Forgy | M |
| 3 | Git dans l'arbre de fichiers | M |

Taille : S ≈ 1 à 2 sessions, M ≈ 3 à 5, L ≈ 6 et plus.

Maquettes dans le canvas *DevForge — maquette 2.0* (section v3.7), choisies le 28/10 : **Tests A** (une colonne, bilan en quatre cartes, tests par fichier, l'échec déplié sur place) et **Git A** (couleurs et lettres M/A/D dans l'arbre, point sur les dossiers, filtre « Modifiés seulement », diff unifié dans l'aperçu).

## Lot 1 — Onglet Tests : trouver, lancer, lire

Un onglet **Tests** dans la fiche d'un projet qui en a (et dans le panneau d'un projet de groupe) :

| Outil | Reconnu par | Lancé avec | Résultats lus dans |
|---|---|---|---|
| Vitest | `vitest` dans les dépendances | `npx vitest run --reporter=json --outputFile=…` | le JSON |
| Jest | `jest` dans les dépendances | `npx jest --json --outputFile=…` | le JSON |
| Playwright | `@playwright/test` | `npx playwright test --reporter=json` | le JSON (sortie standard) |
| PHPUnit | `vendor/bin/phpunit` ou `bin/phpunit` | `… --log-junit …` | le XML JUnit |
| pytest | `pytest` dans les dépendances Python, `pytest.ini`, `conftest.py` | `.venv\Scripts\python -m pytest --junitxml=…` | le XML JUnit |
| Go | `go.mod` et des `*_test.go` | `go test -json ./...` | le flux JSON |
| Cargo | `Cargo.toml` | `cargo test` | le texte (`test … ok / FAILED / ignored`) |

- **Lancer les tests** : la sortie défile pendant l'exécution, **Arrêter** coupe ; puis la liste des tests, regroupés par fichier, avec ✓, ✗ ou *ignoré* et le temps de chacun ; en haut, le bilan (*42 réussis, 2 échoués, 1 ignoré, 3,4 s*).
- Plusieurs outils dans un projet (Vitest et Playwright) : un sélecteur.
- Le rapport s'écrit dans les données de DevForge, jamais dans le projet. La dernière exécution est gardée : l'onglet la remontre à l'ouverture (*il y a 5 min*).
- Python passe par l'environnement virtuel du projet ; un outil absent est signalé avec sa commande d'installation.

**Fini quand** les tests de DevForge (Vitest) s'affichent un par un, et qu'un projet pytest et un projet Cargo aussi.

## Lot 2 — Les échecs, relancer, Forgy

- Un test échoué se déplie : le message, **attendu** et **reçu** quand l'outil les donne, l'endroit (`fichier:ligne`) ; un clic sur l'endroit ouvre le fichier dans l'onglet Fichiers, à la ligne.
- **Relancer les échecs** (seulement les fichiers qui ont échoué), **Relancer ce fichier**, filtre **Échecs seulement**.
- **Expliquer avec Forgy** sur un échec : le test, son message et la sortie partent dans une question à Forgy.

**Fini quand** un test cassé exprès montre son attendu et son reçu, se relance seul, et que Forgy reçoit l'échec.

## Lot 3 — Git dans l'arbre de fichiers

- Dans l'arbre, les fichiers **modifiés** en orange, **nouveaux** en vert, **supprimés** barrés (comme VS Code) ; un dossier qui contient des changements porte un point.
- Un filtre **Modifiés seulement** : l'arbre réduit aux fichiers changés (les supprimés compris).
- Dans l'aperçu d'un fichier changé, **Changements** : le diff (ajouts en vert, retraits en rouge, numéros de ligne) ; un fichier nouveau s'affiche en entier, en ajout.
- Un projet dans un sous-dossier d'un dépôt (un projet de groupe) : les chemins se rapportent bien à lui. Hors d'un dépôt Git : rien ne change.

**Fini quand** un fichier modifié, un nouveau et un supprimé se voient dans l'arbre, et que le diff du modifié s'affiche.

## Lot 4 — Documentation et vérification

- Pages du site (français et anglais) : l'onglet Tests, Git dans l'arbre.
- Vérifié sur de vrais projets : DevForge (Vitest), un projet pytest dans un `.venv`, un projet Cargo, et un dépôt avec des changements.
