# Feuille de route v4.0 — Lancement public

**Cap** : DevForge sort du cercle des amis. Le logiciel est sûr à installer et à utiliser par des inconnus, on sait combien de personnes le téléchargent, et tout ce qu'un nouveau venu voit (installeur, dépôt, site) est fini.
**Base** : v3.9.0.

## Vue d'ensemble

| Lot | Contenu | Taille |
|---|---|---|
| 1 | fait : Electron 44.10, react-router 7, vite 6.4, electron-vite 5, vitest 4 (`npm audit` à 0, vérifié dans la CI) ; permissions limitées au micro, presse-papiers et notifications ; navigation limitée aux pages de l'app, pas de webview ; fusibles (pas de RunAsNode, NODE_OPTIONS ni --inspect, intégrité de l'asar) vérifiés sur l'installeur ; `launch` sans shell pour un vrai programme ; e2e `security` (script injecté, réseau, navigation, permissions) | M |
| 2 | fait : page cachée `/admin` du site, réservée au propriétaire (jeton GitHub) : téléchargements par version, vérifications de mise à jour, visites, clones, origines, étoiles ; archive quotidienne dans le dépôt privé `devforge-stats` (workflow Stats) ; aucune télémétrie, voir docs/dev/stats.md | M |
| 3 | Installeur signé (fin de l'alerte SmartScreen) | S |
| 4 | Le dépôt et le site prêts pour le public | S |
| 5 | Vérification de bout en bout et lancement | S |

Taille : S ≈ 1 à 2 sessions, M ≈ 3 à 5, L ≈ 6 et plus.

## Bilan de l'audit (30/10/2026)

Ce qui est déjà bon :

- les trois fenêtres ont `contextIsolation`, `sandbox` et pas de `nodeIntegration` ; les liens s'ouvrent dans le navigateur, la page ne peut pas partir ailleurs sur le web ;
- les secrets (SSH, bases, GitHub, Vercel, n8n, VPN, clé de Forgy, `.env`) sont chiffrés par `safeStorage` ;
- les serveurs locaux (proxy des domaines, webhooks, tunnels SSH) n'écoutent que sur `127.0.0.1` ;
- Forgy ne lit jamais les fichiers secrets ; ses actions demandent une confirmation ;
- les notes riches passent par une liste blanche de balises ; le code affiché est échappé ;
- aucune faille connue dans les dépendances livrées avec l'app (hors Electron, voir plus bas).

Ce qui manque, par gravité :

| Gravité | Constat | Lot |
|---|---|---|
| — | ~~Aucune Content-Security-Policy~~ : erreur de l'audit, elle est posée au build par `electron.vite.config.ts` sur les trois pages (pas de script en ligne, pas de réseau) ; un test e2e la prouve désormais | 1 |
| Haute | **Electron 44.5.1** : correctif de sécurité en 44.10.0 (certificats eMudhra compromis) ; `npm audit --omit=dev` ne le voit pas, Electron étant en devDependencies alors qu'il est livré | 1 |
| Moyenne | Aucun filtre de **permissions** : Electron accorde par défaut caméra, micro, position, notifications… à la page | 1 |
| Moyenne | La navigation accepte **n'importe quel `file://`** : une page locale ouverte dans la fenêtre aurait le pont `window.devforge` | 1 |
| Moyenne | **Fusibles Electron** non réglés : `RunAsNode` et `NODE_OPTIONS` actifs, pas de contrôle d'intégrité de l'asar | 1 |
| Moyenne | **Installeur non signé** : Windows affiche « Windows a protégé votre ordinateur » à chaque nouvel utilisateur | 3 |
| Basse | react-router 7 (redirection ouverte, sans effet avec le routeur par hash mais à monter), vite, vitest, esbuild (outils de dev seulement) | 1 |
| Basse | `safe.ts` et `ides.ts` lancent des programmes par le shell avec des guillemets ajoutés à la main : à passer sans shell quand c'est possible | 1 |

## Lot 1 — Sécurité

- **CSP stricte** sur `index.html`, `launcher.html`, `widget.html` (`default-src 'self'`, pas de script en ligne, `connect-src` limité à ce dont le renderer a vraiment besoin, images `data:`/`blob:`), posée aussi par en-tête de session pour la version empaquetée ; un test e2e vérifie qu'un `<script>` injecté ne s'exécute pas.
- **Permissions** : `setPermissionRequestHandler` et `setPermissionCheckHandler` n'accordent que le micro (dictée) et le presse-papiers ; tout le reste refusé.
- **Navigation** : seules les pages de l'app (le fichier `out/renderer/…` exact, ou le serveur de dev) ; `will-attach-webview` refusé.
- **Fusibles** (`@electron/fuses` dans electron-builder) : `RunAsNode` off, `EnableNodeOptionsEnvironmentVariable` off, `EnableNodeCliInspectArguments` off, `EnableEmbeddedAsarIntegrityValidation` et `OnlyLoadAppFromAsar` on.
- **Dépendances** : Electron 44.10+, react-router 7.18.5+, vite 8.3.5+, vitest 5.0.5+ ; `npm audit` au vert (y compris Electron) dans la CI.
- **Pont IPC** : relecture des 330 handlers qui prennent un chemin, une commande ou une URL (validation côté main, pas de shell quand ce n'est pas un terminal).
- `SECURITY.md` : comment signaler une faille (adresse, délai de réponse).

## Lot 2 — Statistiques

Sans rien changer à la promesse « pas de compte, pas d'analytics » de la page Vie privée, et visibles par le seul propriétaire :

- une page **`/admin`** sur le site, sans lien ni indexation, qui lit GitHub avec le jeton du propriétaire : téléchargements par version (installeurs), vérifications de mise à jour (`latest.yml`, l'indication de l'usage réel), visites et visiteurs uniques, clones, sites d'origine, pages vues, étoiles ;
- un **workflow quotidien** qui archive ces chiffres (GitHub n'en garde que 14 jours) dans le dépôt privé `devforge-stats`, pour des courbes dans le temps.

Mise en place et détails : [docs/dev/stats.md](../dev/stats.md).

## Lot 3 — Installeur signé

- Signature du code Windows : **SignPath Foundation** (gratuit pour l'open source, signature faite dans GitHub Actions) ou un certificat payant ; l'installeur et les mises à jour signés, `publisherName` vérifié par electron-updater.
- La page Télécharger donne l'empreinte SHA-256 de chaque installeur.

## Lot 4 — Dépôt et site prêts pour le public

- README : capture, ce que fait DevForge en trois lignes, téléchargement, badges (version, téléchargements, licence).
- `CONTRIBUTING.md`, modèles d'issue (bug, idée), Discussions activées, sujets du dépôt.
- Site : page Télécharger relue, Nouveautés à jour (v3.9, v4.0), annonce.

## Lot 5 — Vérification et lancement

- Installation propre sur une machine (ou une VM) Windows neuve : SmartScreen, premier lancement, mise à jour depuis la version d'avant.
- Toute la CI et l'e2e au vert, puis release v4.0.0.
