# Feuille de route v3.5 — Tous mes projets, partout

**Cap** : DevForge trouve tous tes projets, où qu'ils soient et même rangés à plusieurs dans un dossier, les ouvre dans ton IDE, et chaque outil explique ce qu'il fait avec un exemple.
**Base** : v3.4.1.

## Avant : la 3.4.1

Des corrections, sans nouveauté.

**Interface**
- le bouton d'IDE des cartes et de la fiche projet suit l'IDE choisi dans les paramètres (il restait sur « VS Code » après avoir choisi PhpStorm) ;
- l'onglet Projets n'affiche que les filtres des langages qu'on a (pas de « Rust » sans projet Rust).

**Page d'accueil et auth des projets créés** (essais du 28/10 : Symfony, React, Next.js, Node)
- la page d'accueil sait qu'on est connecté : « Tableau de bord » et « Se déconnecter » à la place de « Se connecter » / « Créer un compte » (Twig `app.user`, Blade `@auth`, `/api/auth/me` côté Next.js, React et Vue) ;
- **Symfony** : le contrôleur d'accueil ne contient plus de HTML, il rend une vue Twig (`templates/home/index.html.twig`) ; contrôleurs pour les routes, Twig pour le rendu ;
- **React** (et le même rangement pour Next.js) : le CSS sort du code dans des fichiers `.css` ; un dossier pour les appels à l'API (`src/api/`) et un pour les pages (`src/pages/`) ;
- **Node** : plus de page d'accueil (un projet Node n'a pas de rendu) : `index.js` simple comme avant, et un `npm test` qui vérifie qu'il répond.

**Création**
- **Symfony** : `symfony new … --no-git`, sinon le premier commit part sur `master` (le dépôt de la CLI passait avant le nôtre) ;
- **Next.js avec SQLite** : la base (`dev.db`) n'entre plus dans Git (`.gitignore`) ;
- **Prisma** : la bannière « Update available → 8.0.0-rc » est masquée (`PRISMA_HIDE_UPDATE_MESSAGE`).

Les lots 1 et 2 changent la façon dont DevForge trouve les projets : maquettes de la liste et de la carte « groupe » (canvas *DevForge — maquette 2.0*) avant le code. Le lot 6 aussi.

## Lot 1 — Plusieurs dossiers de projets

Aujourd'hui, un seul dossier de projets (Paramètres) ; or on en a souvent plusieurs (« Projet Perso », « Projet Cefim »…).
- Paramètres : une **liste de dossiers** (ajouter, retirer, réordonner) ; le dossier actuel devient le premier, sans rien perdre.
- **Rescanner** parcourt tous les dossiers ; chaque projet détecté dit d'où il vient (le nom du dossier, discret, sur la carte) ; un filtre par dossier quand il y en a plusieurs.
- **Nouveau projet** : la destination propose ces dossiers.
- Un dossier qui n'existe plus est signalé, pas une erreur.

**Fini quand** des projets de deux dossiers différents apparaissent ensemble, chacun avec son dossier, et qu'un nouveau projet peut naître dans l'un ou l'autre.

## Lot 2 — Projets imbriqués et leurs bases

Un dossier qui n'est pas un projet mais en contient plusieurs (`FreelanceManager/` → `backend/` et `frontend/`) n'est aujourd'hui ni détecté ni utilisable.
- Le scanner descend d'un niveau (deux au plus) quand un dossier n'a pas de marqueur de projet mais que ses sous-dossiers en ont (`package.json`, `composer.json`, `pyproject.toml`…) ; `node_modules`, `vendor`, dossiers cachés et de build exclus.
- **Carte « groupe »** : le nom du dossier parent, ses sous-projets avec leur techno (ex. Symfony + React), ouverture du groupe entier dans l'IDE ou d'un sous-projet ; affichage différent d'un projet simple (à maquetter).
- **Fiche du groupe** : les sous-projets côte à côte, chacun avec ses scripts, son Git (un dépôt commun ou un par sous-projet) et ses onglets.
- **Bases de données** : la détection (`.env`, `compose.yaml`, `DATABASE_URL`…) parcourt aussi les sous-projets, et la base trouvée est rattachée au sous-projet et au groupe.
- Un projet déjà enregistré qui fait partie d'un groupe n'est pas dédoublé.

**Fini quand** `FreelanceManager` apparaît comme un groupe back + front, que chacun s'ouvre et lance ses scripts, et que la base du back est détectée.

## Lot 3 — IDE personnalisés

- Liste élargie, détectée quand l'IDE est installé : VS Code, Cursor, Windsurf, Antigravity, Zed, Sublime Text, la famille JetBrains (PhpStorm, WebStorm, IntelliJ IDEA, PyCharm, Rider, GoLand…), Visual Studio, Notepad++.
- **Ajouter un IDE** : un nom, le chemin de l'exécutable (choisi dans l'explorateur), les arguments (par défaut le dossier du projet), un bouton **Essayer** avant d'enregistrer ; modifiable et supprimable.
- Partout où un projet s'ouvre (cartes, fiche, lanceur, widget, Forgy), le bouton porte le nom et l'icône de l'IDE choisi ; un IDE par projet possible (par ex. PhpStorm pour le back, Cursor pour le front).

**Fini quand** Antigravity, ajouté à la main, ouvre un projet depuis sa carte, et qu'un projet garde son propre IDE.

## Lot 4 — Aide et exemples dans la boîte à outils

Chaque outil dit ce qu'il fait et montre à quoi ça ressemble, pour qui ne le connaît pas :
- en tête de chaque onglet : une phrase « à quoi ça sert » et « comment faire », et un ou plusieurs exemples ;
- **Regex** : exemples grisés dans les champs (motif et texte), et des modèles cliquables (e-mail, date, URL, numéro de téléphone) qui remplissent les deux champs ;
- **Snippets** : un snippet d'exemple et une description du principe ;
- **Diff texte** : une description et deux textes d'exemple qu'on peut charger ;
- **Webhooks** : une URL d'exemple volontairement invalide (`https://exemple.invalid/…`) et un corps d'exemple, pour voir la forme sans rien envoyer pour de vrai ;
- les autres onglets de la boîte à outils : même principe ;
- textes en français et en anglais ; les exemples ne s'enregistrent pas tant qu'on ne les a pas modifiés.

**Fini quand** chaque onglet de la boîte à outils a sa description et au moins un exemple, et qu'aucun exemple ne déclenche d'action réelle.

## Lot 5 — Commandes perso dans la doc

- **Ajouter une commande** dans la doc : la commande, une description, une catégorie (ou une nouvelle) ; modifiable et supprimable ; rangée avec les autres et dans la recherche.
- **Vérification** : la commande (son premier mot) est cherchée sur le PC (`where` sous Windows) ; introuvable, le formulaire le dit (on peut quand même l'enregistrer, par ex. pour un serveur distant).
- **Autocomplétion** en tapant : les exécutables du PATH, les commandes déjà dans la doc, et les sous-commandes connues (`git`, `npm`, `composer`, `php artisan`, `bin/console`…).
- Les commandes perso s'exportent avec les données de DevForge.

**Fini quand** une commande ajoutée, vérifiée et complétée en la tapant, se retrouve dans la doc et dans sa recherche.

## Lot 6 — Suggestions dans le terminal

PowerShell complète déjà avec Tab : DevForge ne la refait pas. Il ajoute :
- des **suggestions grisées** en fin de ligne (comme le shell fish), tirées de l'historique du projet et des commandes de la doc ; → ou Fin pour accepter, rien ne change si on continue de taper ;
- les **scripts** du projet (`npm run …`, `composer …`) en tête des suggestions ;
- désactivable dans les paramètres ; rien n'est envoyé hors du PC.

Maquette d'abord : la suggestion doit rester lisible sans gêner la saisie.

**Fini quand** une commande tapée la veille revient en suggestion, s'accepte d'une touche, et que la saisie normale n'est jamais ralentie.

## Lot 7 — Documentation et vérification

- Pages du site (français et anglais) : dossiers de projets, projets imbriqués, IDE personnalisés, aide de la boîte à outils, commandes perso, suggestions du terminal.
- Vérifié sur de vrais dossiers : « Projet Perso » et « Projet Cefim » ensemble, `FreelanceManager` en groupe avec sa base, un IDE ajouté à la main.

**Fini quand** chaque nouveauté a sa page de doc dans les deux langues, et que les vérifications ci-dessus passent.

## Après : la 3.5.1

Retours d'essai de la 3.5.0 (28/10).

**Projets**
- **Carte « groupe »** : repliée, plus de bouton dont le texte passe sur deux lignes (« Groupe dans VS Code » devient le nom de l'IDE, le détail en infobulle) ; dépliée, elle prend deux colonnes sans laisser de trou dans la grille (les cartes suivantes remontent dans la place libre).
- Sur la ligne des filtres, un bouton **Ajouter un dossier** mène aux dossiers de projets dans les Paramètres.
- **Fichiers du groupe** : ce qui n'est pas un projet (`docs/`, `infra/`, `README.md`, `Dockerfile`, `compose.yaml`, PDF…) fait aussi partie du groupe : la carte le signale, la fiche le montre.
- **Aperçu des fichiers** : un clic sur un fichier de l'onglet Fichiers l'ouvre à côté de l'arbre : Markdown mis en forme (pas le code source), images, PDF, texte et code en police fixe ; les fichiers trop gros ou binaires le disent.

**Base de données**
- **Tables** : créer une table (nom, colonnes : type, nul ou non, défaut, clé primaire, auto-incrément), la renommer, la supprimer (en retapant son nom) ; dans **Structure**, ajouter, renommer, modifier et supprimer une colonne.
- Chaque changement montre d'abord la requête SQL qui va partir ; rien ne s'exécute sans **Appliquer**. SQLite ne sait pas changer le type d'une colonne : le formulaire le dit.
- Résultats : **CSV** ou **JSON** au choix pour la copie (le choix est gardé).

**Console**
- Fermer le dernier onglet de la console du bas la ferme entièrement (elle repart sur un PowerShell neuf à la prochaine ouverture) ; un bouton **Masquer** à droite des onglets la cache sans fermer les shells.
